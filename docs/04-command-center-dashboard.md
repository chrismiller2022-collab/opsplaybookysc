# Client Command Center (Demo): dashboard spec

Live: https://claude.ai/artifact/GNgRXy4sS55GKZks5nE2R4 (claude.ai Dashboard artifact; private until shared). Source page: `dashboard/index.html`. Data: `data/*.csv`, generated by `scripts/generate_demo_data.py` (seed 42).

## Purpose

This is a portfolio demo for cold outreach and interviews. It shows how one administrator keeps five client clubs under control from one screen: what's overdue, what's due soon, which client is slipping, and what families ask about most. **All data is invented.** "Now" is fixed at **2026-10-13 17:00**.

## Layout (top to bottom)

1. **Header:** title, a one-line takeaway computed from the data (for example, "1 request open more than 2 days: clear it first, then the 9 deadlines due in the next two weeks."), and a demo-data note.
2. **Five KPI tiles:** open requests · overdue (open over 48 h, red if over 0) · median first response in hours (green if under 4) · share resolved within 48 h (red if under 95%) · deadlines due in the next 14 days.
3. **Upcoming deadlines table** (soonest first; days left shown in red at 3 or fewer) and a **client health table** (platform, open, overdue, median first reply, registration pace vs last year, red if under 95%).
4. **Requests per week** bar chart (weeks starting Monday; the current, partial week is muted) and a **registration pace** horizontal bar per client, with a dashed 100% line and clubs under 95% in red.
5. **What families ask about** (by category) and **where requests come in** (by channel) as horizontal bars.

## Data schema

**requests.csv** (293 rows): `id, client, channel, category, received, first_response, resolved, status, hours_to_first_response, hours_to_resolve`
- channel ∈ Email, Phone, Voicemail, Social DM, Team app
- category ∈ Registration, Payment / refund, Schedule change, Uniforms, Sponsor, General question, Complaint
- status ∈ Resolved, Open; timestamps `YYYY-MM-DD HH:MM`; hours fields are blank when not yet reached

**deadlines.csv** (15 rows): `client, task, due` (ISO date)

**registrations.csv**: `client, week_of_registration (1 to 8), this_season (blank after week 6), last_season`. These are cumulative counts. Pace = this_season / last_season at the latest week with data.

**clients.csv**: `client, sport, platform, players`

## Metric definitions

- **Overdue:** status Open and received more than 48 hours before "now".
- **Median first response:** median of `hours_to_first_response` over requests that have one.
- **Resolved within 48 h:** among resolved requests, share with `hours_to_resolve` ≤ 48.
- **Due in 14 days:** deadlines with due date between now and now + 14 days.

## Runtime note

`dashboard/index.html` targets the claude.ai Dashboard artifact runtime. It uses `dash.calc` for each derived table, `dash.data(id)` to read, `dash.onData` to redraw, `dash.colors`, theme CSS tokens (`--cds-*`, `--color-*`) and a global `d3` v7. Marks like `data-source`, `data-field` and `data-row-key` give per-number source citations in that runtime. A standalone version needs a small shim: load the CSVs with `d3.csv`, run the same calc functions, and replace the tokens with CSS variables.
